    Using Minder¶

    Minder watches your cameras, answers questions about what it sees, and controls your smart devices — over Telegram or Discord. This page is everything you need as a user. Nothing here requires reading code.

    Before you start¶

    You need:

    • A machine that stays on — a mini PC, a NUC, an old laptop. Linux (this is developed on Ubuntu under WSL2 and on bare Ubuntu). See Hardware below for what it needs; the short version is 4+ cores, 16GB RAM, and a graphics card is optional.
    • Cameras that speak RTSP. Almost all IP cameras do. You will need their username and password.
    • A Telegram or Discord account to talk to it.

    Optional but recommended: a Home Assistant-compatible smart device or two, if you want Minder to switch things on and off. Home Assistant itself is installed for you — it is part of the stack.

    Also optional: an AI accelerator — an NVIDIA GPU, an Intel iGPU, a Coral or Hailo stick, or a board with a built-in NPU. Minder runs perfectly well without one. If you have one, the setup in step 5 finds it, tells you what else it needs, and — importantly — tells you when it is not being used, which otherwise looks exactly like not having one.

    Hardware¶

    The full guide, by camera count and in both modes, is Hardware sizing; this is the short version. Its measured figures come from the reference box — an i7-8750H (6 cores / 12 threads) with a 4 GB GTX 1050 Ti, eight cameras:

    measured what drives it
    graphics memory 2.9–3.7 GB for the model gemma3:4b, resident (see the model's size below)
    CPU the detector sets it Frigate's detector on the CPU handled eight cameras at capacity, host ~70% busy; decoding is about 0.1 of a thread per camera on a substream or 720p stream
    RAM 4.4 GB of containers at eight cameras plus the OS; add 4–8 GB for Ollama with the model loaded
    disk 0.9 GB for eight cameras recordings of detections and alerts, at the default two-day retention

    The model's size, three ways. gemma3:4b is a 3.3 GB download. Loaded on the graphics card it takes 2.9 GB at its 4096-token context, and up to ~3.7 GB has been measured with an image in the prompt — so plan on 3.7 GB, which is why a 4 GB card is the minimum and the detector moves off it while the model is on.

    Builds that work:

    machine what you get
    No graphics card 6 cores / 12 threads, 16 GB RAM Everything works. The model runs on the CPU: a description takes ~30 s instead of ~7 s and a routed answer 5–8 s. With the model on, keep to 4 cameras or fewer; with MINDER_LLM=off, the CPU detector covers more (see the guide).
    Recommended 6 cores / 12 threads, a 4 GB or larger NVIDIA card, 16 GB RAM The reference box's class: eight cameras, the model on the card, Frigate's detector on the CPU at capacity. A 6–8 GB card can hold the model and the detector together (estimated, not yet measured).
    Without the model the same CPU, any CUDA card from a GTX 1050 Ti up MINDER_LLM=off: the card runs Frigate's detector instead — 10–13 ms an inference against 32 ms on the CPU, the reference box going from 70% busy to 70% idle, measured.

    You do not need two models pulled, and you do not need a 12 GB card. RAM is the thing not to skimp on.

    Installing¶

    1. Docker¶

    curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER      # so you don't need sudo for docker
newgrp docker                      # or just log out and back in

    Check it works: docker run --rm hello-world.

    2. Ollama, and one model (optional)¶

    Skipping this step is a supported setup. Minder works without a language model as a detection-and-alerting appliance: set MINDER_LLM=off in .env and see Running without a language model below.

    Minder's language and vision model runs on the host, not in a container — that is what keeps your camera images inside the house.

    curl -fsSL https://ollama.com/install.sh | sh

ollama pull gemma3:4b           # looks at camera frames AND works out what you are asking for

    A 3.3 GB download (2.9–3.7 GB of graphics memory once loaded — see Hardware). One model, on purpose: it works out what you are asking, chats, and looks at frames, and a 4GB graphics card holds one model of this size — two would evict each other on every message. Setup, camera discovery, device control and the health check are plain code and need no model at all; the appliance sets itself up with Ollama not yet running. It runs on CPU; no GPU required — a GPU makes the vision answers roughly four times faster, and Minder will use one if you have it (see step 5).

    These are the defaults and you can change any of them later, but do not guess at substitutes: the vision model in particular was chosen on a benchmark over real camera frames, and the obvious alternatives failed in ways that matter. One faster, smaller model described "a nighttime scene of a porch with a lit lamp and a door" on a frame that was a blank error screen.

    Use a recent Ollama if you can — 0.32 or newer. Upgrading from 0.21 made Minder's routing more than twice as fast on the same model, and older builds quietly ignore the structured-output format for newer model families, which makes them look broken when they are not.

    Skipping this? You can run entirely on cloud AI instead — set OPENROUTER_API_KEY in step 4 and MINDER_DESCRIBE_PROVIDER=openrouter. It is faster and more detailed, but camera snapshots then leave your network.

    3. Get Minder¶

    Minder is not open source. The repository is private, and this step needs an account that has been granted access — if git clone answers Repository not found, that is what it means, not a broken link. Everything else on this page is readable without it.

    git clone git@github.com:delivstat/minder.git ~/minder
cd ~/minder

    Keep the directory named minder. Docker names your data after it, so a different name means Minder comes up empty and looks like it lost everything.

    4. Configure¶

    cp .env.example .env
nano .env

    .env.example is the short list. Every variable the stack takes — 109 of them, with the default and the reasoning — is in env.sample, generated from the compose file so it is always current; copy a line from there into .env to change it.

    You can genuinely leave all of it blank on a first run — the web interface auto-detects your network and asks for camera credentials during onboarding. Fill these in only if discovery does not find your cameras:

    MINDER_SUBNET=192.168.0    # the first THREE octets of your network, no /24 and no trailing .0
MINDER_CAM_USER=admin      # your cameras' login
MINDER_CAM_PASS=...

    MINDER_SUBNET is a prefix, not CIDR: Minder appends .0/24 itself, so 192.168.0 scans 192.168.0.0/24. Run hostname -I and drop the last number to get yours.

    MINDER_CAM_USER / MINDER_CAM_PASS are the shared login, tried on every camera. A camera with a different password gets its own, either on the portal's Cameras tab or from the host:

    ./minder camera-password 192.168.0.31 admin    # prompts for the password, hidden
./minder camera-password --list                # which cameras have their own
./minder camera-password --clear 192.168.0.31  # back to the shared login

    The password is typed into the terminal, never passed as an argument or sent through chat.

    Telegram, Home Assistant and cloud AI are all set up later through the web interface — nothing here needs them.

    chmod 600 .env                 # it will hold passwords and tokens

    5. Start it¶

    ./minder bootstrap        # look at this machine, say what it needs, write .env
./minder up               # build, start, and wait until Minder can answer

    bootstrap asks before writing anything, and writes only .env. If your machine has a GPU or an AI accelerator it will tell you what else is needed to use it — and what happens if you skip that, which differs: an NVIDIA card without its toolkit stops the stack from starting at all, while a Coral or Hailo without its driver lets everything start and quietly run on the processor instead.

    The first run downloads a few GB and takes 10–20 minutes. ./minder up waits for it and tells you when it is ready. To watch:

    ./minder logs minder

    It is ready when you see Application startup complete — though ./minder up has already waited for that, so you only need the logs if something looks wrong.

    Check what it is running on:

    ./minder status

    This is the command to remember. It shows which services are up, which processor is doing the vision work, and anything that is working but not the way you configured it. The line to look for:

    !! MISMATCH   host sees 'cuda', container sees 'generic-cpu'
              the accelerator is not reaching Minder — it is running on the CPU

    That means you have hardware Minder cannot reach — everything works, just slowly, and nothing else would have told you.

    6. Set it up¶

    Open the web interface in a browser on the same network:

    hostname -I | awk '{print $1}'    # e.g. 192.168.0.42 → open http://192.168.0.42

    Use the IP address. You will see http://minder.local in older notes; that only resolves if the host is actually named minder and is running an mDNS responder (avahi-daemon on Linux, Bonjour on macOS). Neither is installed by Minder, so on a fresh box the name will not work and the IP always will. If you want the friendly name:

    sudo hostnamectl set-hostname minder
sudo apt install -y avahi-daemon

    Sign in with admin / minder, then change it. That default is published, so until you change it anyone on your network can sign in — Minder prints a warning at every start until you do. Change it under Settings → Dashboard Password.

    Then:

    1. Add cameras. Minder scans your network and lists what it finds. Confirm the ones you want and give each a name you would actually say out loud — "Front Door", "Side Gate", "Driveway". Those names are what you use when talking to it. Behind the name each camera has a permanent ID, so renaming one later does not break its rules or history.
    2. Connect a messaging channel. Telegram or Discord. Scan the QR code, and the bot will message you to confirm.
    3. Connect Home Assistant if you have smart devices. Minder discovers them; you pick which it may control.

    That is the whole setup. Everything else is conversation.

    Keeping it running¶

    ./minder status                    # what's running, on what silicon, and anything not right
./minder logs minder               # follow a service's logs
./minder restart                   # down then up, if something seems stuck
./minder down                      # stop everything (your data is kept)
./minder up                        # build, start, and wait until it can answer
./minder build                     # build the image without starting it
./minder bootstrap                 # re-detect this machine and rewrite .env (asks first)
./minder camera-password <ip>      # give one camera its own password (also --list, --clear <ip>)
./minder migrate-cameras           # report the camera-ID migration; --apply to run it
./minder search enable             # semantic search on (also disable, status)
./minder face-model status         # face recognition's model (also install <m>, use <m>)

    ./minder status is the one to reach for first. As well as which services are up, it reports which processor is doing the vision work — and says so plainly when an accelerator you have is not being used, which otherwise looks exactly like not having one.

    Minder backs itself up nightly to ~/minder/backups. To update:

    cd ~/minder && git pull && ./minder up

    Talking to it¶

    Just write normally. Minder works out what you meant.

    Ask what it sees

    "is someone at the main door" "do you see anyone outside?" "is the gate open?" "is there a car in the driveway" "show me the porch"

    It looks at the camera now, describes what is actually in frame, and sends the snapshot.

    Control things

    "turn off the pressure pump" "switch on the solar heater"

    Set up rules — this is the part people underuse:

    "turn on the pump when there is a person at the main door" "every night at 9pm turn on the porch light" "switch off the pump when the water level is reached"

    Minder writes the rule, shows it back to you, and runs it from then on. To see, switch off or delete rules, use the portal's Rules tab — chat creates rules but does not list or remove them.

    Ask about the house

    "what cameras do I have" "what smart devices are connected" "is it raining outside?" "anything at the door today?"

    If it misunderstands you¶

    It gets the intent right about 92 times in 100 — measured, not a guess, on a 184-case benchmark of real phrasings, the hard ones added from earlier misreadings. When it gets one wrong, the most useful thing you can do is reply wrong. Minder records the message it misread, asks what you meant, and wrong: query (or snapshot, device_now, scenario, …) files it as a test case that the next version is checked against. Beyond that, three things help:

    • Name the camera. "anything on the side gate" is more reliable than "anything out back", because Minder matches your configured camera names exactly. Names it does not know ("the veranda") are where it struggles most.
    • Say what you want done. "turn the pump off" rather than "the pump" — a command without an action reads as a question about your devices.
    • Say when for a rule. "turn on the pump when someone is at the door" creates a standing rule; without a when/if/every, the same words are treated as "do it now".

    Every message you send is recorded with what Minder thought you meant, so misreadings can be found and fixed rather than guessed at. Set MINDER_ROUTER_LOG=off if you would rather it did not.

    Knowing who is who (optional)¶

    Minder can put names to faces — but only for people you deliberately enrol, and only if you install the face plugins. Nothing about faces is stored or computed until you do.

    The most useful thing it does needs no enrolment at all: telling you that someone is a stranger. A stranger is a face that matched nobody, so "alert me if an unrecognised face is at the gate after dark" works for people who have never been near your house.

    If you also enrol the people who live and work there, alerts can say "Alex at the main door" instead of "person at the main door", and you can write rules about groups — "anyone who is not family, after 10pm".

    A recognised face never silences an alert. It changes the words, never whether you are told. So if it misidentifies someone, you get a wrong name — never a missed intruder.

    Alerts¶

    When a camera detects something worth telling you about, Minder sends a message with a snapshot and a short description of what it is — not just "motion detected", but what is actually there.

    Alerts come only from rules, so both kinds of problem are fixed in the portal's Rules tab:

    If you get too many alerts, narrow the rule — fewer cameras, or night only instead of always — or switch it off. Chat cannot remove or change a rule.

    If you are missing alerts, check there is an enabled rule covering that camera at that time of day. Asking "what did you not tell me about last night" lists the detections that did not alert, and why (no rule, cooldown, or the second look disagreed).

    Asking what happened¶

    "what happened today between 11 and 3" "did anyone come to the main door this afternoon" "was there a car at the porch yesterday" "who was at the door this morning" / "did anyone unknown come today" "what did you not tell me about last night"

    Minder answers from its own record of every camera event — the ones it alerted you about and the ones it did not (no rule, cooldown, or the second look disagreed), each marked as such — with the times in your clock and the top events with their photos. If a camera was offline for part of the window it says so, because "nothing happened" is only true if Minder was looking. The dashboard's Events tab has the same query as a form.

    With search switched on (./minder search enable), you can also ask by how something looked: "show me the light green car this week", "someone carrying a bag at the door". Minder answers with the closest matching events, best first, and never claims a match is certain. See Searching what the cameras saw (search.md).

    Snapshots, video and history¶

    Every alert is kept. In the web UI you can scroll back through events, view the snapshot or the clip, and mark things as seen. Ask in chat too: "anything at the gate yesterday?"

    When Minder tells you something is wrong¶

    A health monitor checks every 45 seconds that each part — the agent runtime, Frigate, Home Assistant, Ollama, the chat adapters — is not just running but working. When something goes down or comes back it sends you a message, over whichever channel is up. It reports; it never restarts anything. The current picture is under Settings → Health & Recovery, or send /health on Telegram.

    Every six hours, and at start, it also checks Minder's own saved state. If a file is damaged or missing, it asks you first: /approve restores it from the last backup, /reject leaves it. It never repairs anything on its own.

    Running without a language model¶

    Set MINDER_LLM=off in .env (then ./minder up) and Minder never calls a language model. You don't need Ollama at all, and the appliance fits smaller boxes: the model alone needs about 3.7 GB.

    Everything that watches and alerts works exactly the same:

    • detection on every camera, rules, and alerts with the photo (every detected object boxed) and the clip;
    • face recognition, recognising returning visitors, and detection plugins;
    • the full event history, and search if you turn it on (its model is not a language model);
    • Home Assistant devices and automations;
    • the whole web portal: cameras, live view, events, history, people, rules, settings.

    Chat still answers questions; it just stops chatting. Messages are understood by code instead of a model:

    Ask Works
    "is anyone at the main door?", "how many cars are on the driveway?" ✓ checks the camera now
    "show me the porch", "video from the gate" ✓
    "who was at the door last night?", "what happened this afternoon?", "did Alex come home today?" ✓ from the history
    "when did someone in a red jacket come by this week?" ✓ with search on
    "turn off the pump", "list my devices", "list cameras", "weather" ✓
    "alert me if more than 3 cars are on the driveway" ✓ count rules
    "what's happening on the porch?" what the detector sees there ("Porch: 1 person, 1 car"), not a description in words
    "when someone is at the gate after 10pm, turn on the porch light" add it in the portal's Rules tab: other rule sentences need the model
    general conversation a short menu of what you can ask

    Two things change with alerts:

    • Alert photos come without the one-line description of who or what is in them.
    • A rule you gave a severity check (a second look by the vision model) fires as a plain alert marked "unconfirmed", because there is no model to confirm it. It still fires, every severity.

    The NVIDIA graphics card, if you have one, moves to detection. With the model off, Frigate's detector runs on the card instead of the CPU: 10–13 ms an inference instead of 32 ms on the reference box. It no longer skips frames in rain or wind, and the CPU goes from 70% busy to 70% idle. With the model on, a 4 GB card is the model's, and the detector moves back to the CPU, because the two sharing one 4 GB card slows both (see Hardware sizing). The switch happens when Minder starts, so ./minder up after changing MINDER_LLM is all it takes. The health page shows where the detector runs and why.

    The health page shows the language model as "not used (MINDER_LLM=off)", not as a fault. Set MINDER_LLM=on and restart to bring everything back.

    Privacy¶

    By default nothing leaves your house. Camera images are analysed by a model running on the appliance itself.

    Cloud AI is opt-in and used only when you turn it on — it is better at detailed scene descriptions, and it is what powers one-time training when you teach Minder to recognise something new. When it is off, Minder still works; descriptions are just less detailed.

    Your recordings are never uploaded. A snapshot goes to a cloud model only if you set an OpenRouter key — for the features you switched to cloud, and for the second look on rules marked critical. Privacy has the details, including how to keep critical rules local.

    Troubleshooting¶

    What you see What to do
    Bot does not reply Check the appliance is on — the web interface at its IP should load.
    "I can't reach that camera" The camera is offline or changed IP. Re-run discovery in the web UI.
    Alerts stopped Check the rule is still enabled in the Rules tab, and the camera is online on the Cameras tab.
    Device won't switch Home Assistant may have lost the device. Check Settings → Health & Recovery, and the device in Home Assistant.
    Everything seems stuck Run ./minder status on the host, and look at Settings → Health & Recovery — both say what is down.

    If you need to start clean, the web UI has a backup and restore page. Minder backs itself up nightly, so restoring is usually faster than reconfiguring.

    Where the appliance lives¶

    Minder runs from ~/minder on the host, as a set of Docker containers. Day to day you should never need to touch that — but if you want the technical picture, see the architecture guide.
