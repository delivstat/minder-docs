    Using Minder¶

    Minder watches your cameras, answers questions about what it sees, and controls your smart devices — over Telegram or Discord. This page is everything you need as a user. Nothing here requires reading code.

    Before you start¶

    You need:

    • A machine that stays on — a mini PC, a NUC, an old laptop. Linux (this is developed on Ubuntu under WSL2 and on bare Ubuntu). 16GB RAM is comfortable; 8GB works if you use cloud vision.
    • Cameras that speak RTSP. Almost all IP cameras do. You will need their username and password.
    • A Telegram or Discord account to talk to it.

    Optional but recommended: a Home Assistant-compatible smart device or two, if you want Minder to switch things on and off. Home Assistant itself is installed for you — it is part of the stack.

    Also optional: an AI accelerator — an NVIDIA GPU, an Intel iGPU, a Coral or Hailo stick, or a board with a built-in NPU. Minder runs perfectly well without one. If you have one, the setup in step 5 finds it, tells you what else it needs, and — importantly — tells you when it is not being used, which otherwise looks exactly like not having one.

    Installing¶

    1. Docker¶

    curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER      # so you don't need sudo for docker
newgrp docker                      # or just log out and back in

    Check it works: docker run --rm hello-world.

    2. Ollama, and two models¶

    Minder's language and vision models run on the host, not in a container — that is what keeps your camera images inside the house.

    curl -fsSL https://ollama.com/install.sh | sh

ollama pull gemma3:4b           # looks at camera frames AND works out what you are asking for
ollama pull qwen2.5:3b          # reasoning and tool use (setup, discovery, the doctor)

    Roughly 5GB total. One model does both routing and vision on purpose: a 4GB graphics card holds one model of this size, and two would evict each other on every message. They run on CPU; no GPU required — a GPU makes the vision answers roughly four times faster, and Minder will use one if you have it (see step 5).

    These are the defaults and you can change any of them later, but do not guess at substitutes: the vision model in particular was chosen on a benchmark over real camera frames, and the obvious alternatives failed in ways that matter. One faster, smaller model described "a nighttime scene of a porch with a lit lamp and a door" on a frame that was a blank error screen. MODELS.md in the repository has the comparison.

    Use a recent Ollama if you can — 0.32 or newer. Upgrading from 0.21 made Minder's routing more than twice as fast on the same model, and older builds quietly ignore the structured-output format for newer model families, which makes them look broken when they are not.

    Skipping this? You can run entirely on cloud AI instead — set OPENROUTER_API_KEY in step 4 and MINDER_DESCRIBE_PROVIDER=openrouter. It is faster and more detailed, but camera snapshots then leave your network.

    3. Get Minder¶

    Minder is not open source. The repository is private, and this step needs an account that has been granted access — if git clone answers Repository not found, that is what it means, not a broken link. Everything else on this page is readable without it.

    git clone git@github.com:delivstat/minder.git ~/minder
cd ~/minder

    Keep the directory named minder. Docker names your data after it, so a different name means Minder comes up empty and looks like it lost everything.

    4. Configure¶

    cp .env.example .env
nano .env

    You can genuinely leave all of it blank on a first run — the web interface auto-detects your network and asks for camera credentials during onboarding. Fill these in only if discovery does not find your cameras:

    MINDER_SUBNET=192.168.0    # the first THREE octets of your network, no /24 and no trailing .0
MINDER_CAM_USER=admin      # your cameras' login
MINDER_CAM_PASS=...

    MINDER_SUBNET is a prefix, not CIDR: Minder appends .0/24 itself, so 192.168.0 scans 192.168.0.0/24. Run hostname -I and drop the last number to get yours.

    Telegram, Home Assistant and cloud AI are all set up later through the web interface — nothing here needs them.

    chmod 600 .env                 # it will hold passwords and tokens

    5. Start it¶

    ./minder bootstrap        # look at this machine, say what it needs, write .env
./minder up               # build, start, and wait until Minder can answer

    bootstrap asks before writing anything, and writes only .env. If your machine has a GPU or an AI accelerator it will tell you what else is needed to use it — and what happens if you skip that, which differs: an NVIDIA card without its toolkit stops the stack from starting at all, while a Coral or Hailo without its driver lets everything start and quietly run on the processor instead.

    The first run downloads a few GB and takes 10–20 minutes. ./minder up waits for it and tells you when it is ready. To watch:

    ./minder logs minder

    It is ready when you see Application startup complete — though ./minder up has already waited for that, so you only need the logs if something looks wrong.

    Check what it is running on:

    ./minder status

    This is the command to remember. It shows which services are up, which processor is doing the vision work, and anything that is working but not the way you configured it. The line to look for:

    !! MISMATCH   host sees 'cuda', container sees 'generic-cpu'
              the accelerator is not reaching Minder — it is running on the CPU

    That means you have hardware Minder cannot reach — everything works, just slowly, and nothing else would have told you.

    6. Set it up¶

    Open the web interface in a browser on the same network:

    hostname -I | awk '{print $1}'    # e.g. 192.168.0.42 → open http://192.168.0.42

    Use the IP address. You will see http://minder.local in older notes; that only resolves if the host is actually named minder and is running an mDNS responder (avahi-daemon on Linux, Bonjour on macOS). Neither is installed by Minder, so on a fresh box the name will not work and the IP always will. If you want the friendly name:

    sudo hostnamectl set-hostname minder
sudo apt install -y avahi-daemon

    Then:

    1. Add cameras. Minder scans your network and lists what it finds. Confirm the ones you want and give each a name you would actually say out loud — "Main Door", "Pathway Gate", "Driveway". Those names are what you use when talking to it.
    2. Connect a messaging channel. Telegram or Discord. Scan the QR code, and the bot will message you to confirm.
    3. Connect Home Assistant if you have smart devices. Minder discovers them; you pick which it may control.

    That is the whole setup. Everything else is conversation.

    Keeping it running¶

    ./minder status                    # what's running, and anything not right
./minder logs minder               # what it's doing
./minder restart                   # if something seems stuck
./minder down                      # stop everything (your data is kept)
./minder up                        # start again

    ./minder status is the one to reach for first. As well as which services are up, it reports which processor is doing the vision work — and says so plainly when an accelerator you have is not being used, which otherwise looks exactly like not having one.

    Minder backs itself up nightly to ~/minder/backups. To update:

    cd ~/minder && git pull && ./minder up

    Talking to it¶

    Just write normally. Minder works out what you meant.

    Ask what it sees

    "is someone at the main door" "do you see anyone outside?" "is the gate open?" "is there a car in the driveway" "show me the porch"

    It looks at the camera now, describes what is actually in frame, and sends the snapshot.

    Control things

    "turn off the pressure pump" "switch on the solar heater"

    Set up rules — this is the part people underuse:

    "turn on the pump when there is a person at the main door" "every night at 9pm turn on the porch light" "switch off the pump when the water level is reached"

    Minder writes the rule, shows it back to you, and runs it from then on. You can list and remove rules the same way.

    Ask about the house

    "what cameras do I have" "what smart devices are connected" "is it raining outside?" "anything at the door today?"

    If it misunderstands you¶

    It gets the intent right about 19 times in 20 — that is measured, not a guess, across 166 real phrasings (scripts/bench_router.py if you want to run it yourself). The twentieth time, the most useful thing you can do is reply wrong. Minder records the message it misread, asks what you meant, and wrong: query (or snapshot, device_now, scenario, …) files it as a test case that the next version is checked against. Beyond that, three things help:

    • Name the camera. "anything on bedroom deck" is more reliable than "anything out back", because Minder matches your configured camera names exactly. Names it does not know ("the veranda") are where it struggles most.
    • Say what you want done. "turn the pump off" rather than "the pump" — a command without an action reads as a question about your devices.
    • Say when for a rule. "turn on the pump when someone is at the door" creates a standing rule; without a when/if/every, the same words are treated as "do it now".

    Every message you send is recorded with what Minder thought you meant, so misreadings can be found and fixed rather than guessed at. Set MINDER_ROUTER_LOG=off if you would rather it did not.

    Knowing who is who (optional)¶

    Minder can put names to faces — but only for people you deliberately enrol, and only if you install the face plugins. Nothing about faces is stored or computed until you do.

    The most useful thing it does needs no enrolment at all: telling you that someone is a stranger. A stranger is a face that matched nobody, so "alert me if an unrecognised face is at the gate after dark" works for people who have never been near your house.

    If you also enrol the people who live and work there, alerts can say "Alex at the main door" instead of "person at the main door", and you can write rules about groups — "anyone who is not family, after 10pm".

    A recognised face never silences an alert. It changes the words, never whether you are told. So if it misidentifies someone, you get a wrong name — never a missed intruder.

    Setup, groups, rules, and how to delete someone: Face detection and recognition.

    Alerts¶

    When a camera detects something worth telling you about, Minder sends a message with a snapshot and a short description of what it is — not just "motion detected", but what is actually there.

    If you get too many alerts, say so: "stop alerting me about cars in the driveway", or set quiet hours. Alerting rules are rules like any other.

    If you are missing alerts, check the camera is armed in the web UI. Minder only alerts on cameras you have armed.

    Snapshots, video and history¶

    Every alert is kept. In the web UI you can scroll back through events, view the snapshot or the clip, and mark things as seen. Ask in chat too: "anything at the gate yesterday?"

    When Minder asks you something¶

    Minder runs a health check every six hours. If it finds a problem it can fix — a camera that dropped off, a service that needs restarting — it asks you first and waits.

    It never repairs anything on its own. Reply to approve, or ignore it and nothing happens.

    Privacy¶

    By default nothing leaves your house. Camera images are analysed by a model running on the appliance itself.

    Cloud AI is opt-in and used only when you turn it on — it is better at detailed scene descriptions, and it is what powers one-time training when you teach Minder to recognise something new. When it is off, Minder still works; descriptions are just less detailed.

    Your recordings are never uploaded. Snapshots go to a cloud model only if you enabled cloud vision, and only for the specific question being asked.

    Troubleshooting¶

    What you see What to do
    Bot does not reply Check the appliance is on — the web interface at its IP should load.
    "I can't reach that camera" The camera is offline or changed IP. Re-run discovery in the web UI.
    Alerts stopped Check the camera is still armed, and that quiet hours are not on.
    Device won't switch Home Assistant may have lost the device. Ask "diagnose" and Minder will check.
    Everything seems stuck Ask "diagnose". Minder checks itself and reports what is wrong.

    If you need to start clean, the web UI has a backup and restore page. Minder backs itself up nightly, so restoring is usually faster than reconfiguring.

    Where the appliance lives¶

    Minder runs from ~/minder on the host, as a set of Docker containers. Day to day you should never need to touch that — but if you want the technical picture, see the architecture guide.
