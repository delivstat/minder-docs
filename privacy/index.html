    Privacy¶

    Minder watches your home. That makes what it keeps, and what leaves the house, the most important thing about it — so this page is specific rather than reassuring.

    What never leaves your house by default¶

    Camera frames. Detection, description and recognition all run on the appliance. The vision model is local. Nothing is uploaded to anybody.

    Your recordings. Frigate stores clips and snapshots on the machine's own disk.

    Face templates, if you use recognition. They are computed on the appliance and stored there.

    Your conversations with it. The language model that reads your messages runs locally too, unless you move it to the cloud.

    What can leave, only if you turn it on¶

    Two choices are opt-in and off by default:

    Choice Setting What is sent
    Cloud answers to visual questions only MINDER_QUERY_PROVIDER=openrouter the frame for that one question
    The whole language model in the cloud (guide) MINDER_ROUTER_PROVIDER and MINDER_VISION_PROVIDER set to openrouter every chat message's text with your camera and device names; the frame for each scene question; each alert's frame if descriptions stay on (MINDER_DESCRIBE)

    The first falls back to the local model if the cloud is unreachable. The second has no local model to fall back to: detection and alerts keep working, and chat falls back to the keyword reader Minder uses with the model off. A cloud outage degrades answers; it never stops the appliance watching.

    One path uses the cloud without a separate switch: critical rules. A rule marked severity: critical with a second-look question (an escalate block) asks the cloud vision model to confirm it, and sends that one alert frame, at full resolution, to do so. It only happens if an OpenRouter key (OPENROUTER_API_KEY) is configured; with no key the check runs on the local model. To keep a critical rule local while a key is set, give its escalate block tier: local.

    Alerts themselves go out through Telegram or Discord, which is a deliberate choice you make when you connect a channel: the message and its snapshot pass through that provider like any other chat. If that matters to you, both are optional and Minder works without either.

    Face recognition, if you enable it¶

    Not installed by default and does nothing until you arm it.

    A template exists only because someone deliberately enrolled that person, through a signed-in browser session. There is no chat command, no API token, and no automated path that can enrol anybody — the record names the human who did it and when.

    Stored Not stored
    a mathematical template (512 numbers) the photograph — discarded once the template is computed
    the person's name and group any face template of people you did not enrol
    who enrolled them, and when any link between one stranger and another sighting, unless you arm re-identification (below)

    A template is not a picture and cannot be turned back into one.

    Strangers¶

    An unrecognised face is recorded as "a face, matched nobody" and no template of that face is kept. That is why "was an unrecognised person at the gate last night?" can be answered while "was that the same stranger as Tuesday?" cannot — answering the second would mean keeping biometrics of people who never agreed to it.

    That trade was chosen deliberately, and it is the difference between a system that recognises the people you invited and one that recognises everybody who walks past.

    Person re-identification, if you arm it¶

    A separate plugin, person-reidentify, is not installed by default. When armed, it links sightings of the same unknown person across cameras — the visitor who walked up the drive and is now at the door — by comparing a numeric summary of their body's appearance, not their face.

    • The appearance summaries are held in memory only, for 15 minutes after a person was last seen (MINDER_REID_TTL_S). They are never written to disk, and a restart clears them.
    • The event history records a visitor label such as visitor-3fa9c21e on each sighting. It is random and carries no name. While the label exists, "was that the same person as ten minutes ago?" can be answered for that visit — which is the point of the plugin.
    • If face recognition later names someone on the same camera event, their visit is shown under that name when you ask. The link is worked out at question time and never stored, so deleting the person unlinks those visits too.

    Deleting someone¶

    Deletion removes every template, clears their name from past events — the events remain, only the identification is withdrawn — records what it did, and then re-queries both stores and shows you the result. The screen reports what the check found, not that a request succeeded.

    Guests carry an expiry and are deleted automatically. Someone enrolled for a fortnight's visit will not still be recognised two years later because nobody remembered.

    What the appliance keeps about you¶

    Where Retention
    clips Frigate, local disk 2 days by default (MINDER_RECORD_DAYS)
    snapshots Frigate, local disk 7 days
    the event history a local database until you delete it
    every message you send it the same database, so misroutes can be found MINDER_ROUTER_LOG=off disables
    face templates a separate local database until deleted, or a guest expires
    search index (if enabled) the event-history database: a numeric summary of each event's picture, not the picture until ./minder search disable, which deletes it all

    Face templates live in their own database rather than alongside events, so "delete everything biometric" is one file rather than a search.

    Turning things off¶

    Effect
    MINDER_PLUGINS=off all detection plugins stop, whatever is armed
    MINDER_ROUTER_LOG=off messages are no longer recorded
    ./minder search disable search stops; its model and every indexed event are deleted
    disarm a plugin it stops running, stays installed
    delete a person templates gone, verified
    unplug it it is your machine

    The honest caveats¶

    Alert channels are third parties. Telegram and Discord see the alerts you route through them.

    The portal guards all of this. It is reachable on your local network, and it ships with a published default login, admin / minder. Until you change it, anyone on your network can sign in, and Minder prints a warning saying so every time it starts. Change it under Settings → Dashboard Password on first sign-in. If you use face recognition, that password is what stands between someone on your network and your household's biometric data.

    Cloud features send a real frame. When enabled — or when a critical rule is checked with a cloud key set — the snapshot going to the provider is an actual picture of whatever triggered the alert.
